# IMPLEMENTATION_PLAN — EasySlot V0.1

> 文档版本：v0.1 ｜ 状态：初稿，等待评审 ｜ 最后更新：2026-10-10
>
> 上位文档：`PRODUCT_VISION.md`、`PRD.md`、`CONTENT_DESIGN.md`、`UX_DESIGN.md`、`TECH_DESIGN.md`；视觉 skill `.agents/skills/vibeslot-ui/`。
> 本文把 V0.1 拆成**依赖明确、可逐个验收**的开发任务。任务只规定“做什么、做到什么程度”，具体规则一律引用上位文档，不在这里重复定义。

---

## 1. 执行原则

1. **按顺序推进，每个任务结束都能运行**：`npm run dev` 能打开，`npm run check`、`npm test`、`npm run build` 全部通过。
2. **一次只交给 Agent 一个任务**；任务完成并验收后再开始下一个。不要把多个任务合并成一次提交。
3. **先逻辑后界面**：规则先写成 `engine/`、`state/` 中的纯函数并配测试，再接到组件（TECH §17）。
4. **不超范围**：只实现当前任务列出的内容；后续任务的功能即使顺手也不要提前做。PRD §12 “明确不做”的永远不做。
5. **界面任务必须加载视觉 skill**，并按 skill 的检查清单自查（`AGENTS.md`）。
6. **验收以文档中的验收标准为准**：每个任务列出对应的 PRD 验收条目，逐条勾选；做不到的如实说明。
7. **发现文档冲突或缺口时停下来报告**，不要自行决定产品行为。

## 2. 里程碑

| 里程碑 | 包含任务 | 完成后可以体验到 |
|---|---|---|
| **M1 能转起来** | T01–T05 | 打开 `/play/cook` 等 5 个预设，转动、锁定、依次停止的动画，手感可评估 |
| **M2 完整的预设体验** | T06–T08 | 首页、结果卡片与两类玩法流程、排除 / 尺度 / 可选列 / 内容分组、设置都能用，并在刷新后保留 |
| **M3 自定义与分享** | T09–T11 | 自建老虎机、结果分享、模板短链接分享与导入 |
| **M4 上线** | T12–T13 | 统计、反馈、安全头、生产部署、真机走查、内容抽查 |

**建议在 M1 结束后安排一次手感评审**：转动节奏、落定感、锁定是否好懂。手感是体验核心（Vision §2.1），这时调整成本最低。

```text
请完成 design/IMPLEMENTATION_PLAN.md 中的任务 T0X「任务名」。

开始前：
- 阅读 AGENTS.md，以及该任务“相关文档”中列出的章节。

- 预设内容与界面文案逐字使用文档，不得自行编写。
- 发现文档之间冲突或缺少规则时，停下来列出问题，不要自行决定。

完成后报告：
1. 修改了哪些文件、实现了什么。
```

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 转动手感不达预期 | 核心体验受损 | T05 后安排手感评审；参数集中在一处，便于调整 |
| 4 列在 320px 上过挤 | 自定义 4 列模板难用 | T04 就用 4 列数据验证；必要时缩小列间距或锁定按钮只显示图标（UX §5.5 已允许） |
| 微信内置浏览器兼容问题（系统分享、剪贴板、`dvh`） | 主要传播渠道受影响 | 分享已设三级兜底（TECH §9.1）；`dvh` 有 `vh` 回退；T13 必须在微信中走查 |
| 国内访问 Cloudflare 速度一般 | 打开慢、流失 | 使用自有域名；控制首屏体积；有起色后按 Vision D2 备案迁移 |
| 内容抽查不合格 | 结果荒谬 | 优先修改内容；仅在必要时做 P1-d 互斥规则 |
| Agent 自行发挥（编造文案、加功能、引入依赖） | 返工 | 提示词模板中明确禁止；每个任务按验收标准逐条检查 |
