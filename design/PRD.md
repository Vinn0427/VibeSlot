## 1. V0.1 目标

### 1.1 产品目标

1. 上线一个**无需登录、打开即转**的移动端优先 Web 应用，包含 5 个预设场景和自定义老虎机。【已确认】
2. **转动手感**达到“愿意多转几次”的水准，作为核心体验来打磨。【已确认】
3. 预设内容**任意组合基本成立**，结果大致可执行。【已确认】
4. 结果和模板可以分享，打开分享链接后 **1 次点击即可开始转**。【已确认】
5. 通过轻量统计验证 Vision §11 中的假设 H1–H6。【已确认】

### 1.2 发布标准（V0.1 Done 的定义）

- 本文所有 P0 功能通过验收标准。
- 在 iOS Safari、Android Chrome、微信内置浏览器上完成主流程走查，没有阻断性问题。
- 5 个预设模板的内容通过 CONTENT_DESIGN 中的组合抽查。
- 部署到自有域名，统计事件可以在后台看到。
- 短链接接口与静态站点一同上线，管理脚本可用。

## 2. 术语表

开发时代码命名应与本表保持一致（英文名供 TECH_DESIGN 使用）。

| 术语 | 英文 | 定义 |
|---|---|---|
| 场景 / 模板 | Template | 一台老虎机的完整配置：名称、列、候选项、句式、玩法类型等。“场景”是面向用户的叫法，“模板”是数据层面的叫法 |
| 预设模板 | Preset | 产品内置、只读的模板 |
| 自定义模板 | Custom Template | 用户创建、保存在本机的模板 |
| 列 | Reel | 老虎机的一个属性槽，例如“主料” |
| 可选列 | Optional Reel | 用户可以开关的列，关闭时不参与转动，也不显示 |
| 候选项 | Option | 列中的一个选项，包含标签 `label`，以及可选的尺度 `intensity`、内容标签 `tags`、权重 `weight`。**不设说明字段**，`label` 必须自己就能看懂【已确认】 |
| 可用候选项 | Available Option | 未被排除，且符合当前尺度筛选的候选项 |
| 内容分组 | Tag Group | 模板定义的一类敏感内容（例如“身体接触”“隐私”），对应候选项上的某个 `tag`，可以整组排除或恢复 |
| 结果提示 | Result Note | 模板级的一行固定提示，显示在结果卡片底部（例如调酒比例），可选 |
| 首次须知 | Notice | 模板级的一次性提示，第一次进入该场景时显示，可选 |
| 转动 | Spin | 一次抽奖动作，所有未锁定的列同时滚动，然后依次停止 |
| 锁定 | Lock | 让某一列保持当前结果，不参与下一次转动 |
| 排除 | Exclude | 把某个候选项从滚轮中拿掉，永久保存，可以恢复 |
| 尺度 | Intensity Level | 1–3 级，是候选项的元数据。尺度筛选决定哪些候选项可用 |
| 结果 | Result | 一次转动后各列的取值组合 |
| 结果句式 | Sentence | 模板中带占位的一句话，用结果填充后显示在结果卡片上 |
| 玩法类型 | Mode | `decision`（决策类）或 `game`（游戏类），两类的按钮和流程不同 |
| 重转次数 | Respin Limit | 决策类场景中，第一次转动之后还允许转动的次数 |
| 轮 | Round | 游戏类场景中，一次“转出 → 完成”的过程 |

## 4. 预设场景（V0.1）

列结构为【已确认】或【建议】，具体候选项见 CONTENT_DESIGN。

| 顺序 | 场景 ID | 名称（暂定） | 玩法类型 | 列 | 可选列 | 尺度筛选 | 重转次数默认值 |
|---|---|---|---|---|---|---|---|
| 1 | `cook` | 今天做什么菜 | decision | 主料 × 配菜 × 风味【已确认】 | 无 | 无 | 不限【已确认】 |
| 2 | `date` | 约会去哪 | decision | 主活动 × 吃点什么 × 约会彩蛋【建议】 | 无 | 无 | 不限【已确认】 |
| 3 | `party` | 聚会挑战 | game | 谁来 × 做什么 × 附加条件【建议】 | 无 | 无【已确认：尺度为情侣互动专属】 | 不适用（按轮进行） |
| 4 | `mix` | 便利店调酒 | decision | 基酒 × 饮料【已确认：默认 1 酒 + 1 饮料】 | 再加一种（默认关闭，开启后为 1 酒 + 2 饮料）【已确认】 | 无 | 不限 |
| 5 | `couple` | 情侣互动 | game | 谁主动 × 在哪 × 做什么【已确认：两个主体】 | 附加规则（默认关闭）【已确认】 | 有：温和 / 心动 / 升温 | 不适用（按轮进行） |

补充规则：

- `cook` 的结果卡片显示轻提示“AI 推荐菜谱即将上线”。【已确认】
- `party` 定位为**熟人局**【已确认】：允许不过分的身体接触、真心话和不太冒犯的隐私、联系场外或发布内容；以有趣、烘托气氛为标准，避免尴尬。
- `party` 的敏感内容用内容分组标注，可以整组排除（F22）：身体接触（`touch`）、隐私（`privacy`）【已确认】、场外互动（`outside`，联系场外或发布内容）、饮酒（`alcohol`，**默认整组排除**）【已确认】。
- `party` 的“谁来”列使用相对描述（如“左手边的人”）。【已确认】
- `mix` 是饮酒主题场景：首次进入显示须知“未成年人请勿饮酒，喝酒不开车”；结果卡片显示固定提示（调配比例与理性饮酒）。
- `couple` 的结果句式包含两个主体：主动的一方和对方（例如“你主动，在沙发上公主抱对方”）。【已确认】
- `date` 不做预算筛选，内容控制在中低预算；不喜欢的项可以排除。
- 内容上限为 PG-13。【已确认】
- 尺度筛选仅用于 `couple`，默认档位为 1（温和）【已确认】。
- 不想做的通过“换一个”跳过，长期不想要的通过排除拿掉。

## 5. 核心用户流程

### 5.1 首次使用（决策类）

```
首页 → 点击“今天做什么菜” → 老虎机页（初始状态，滚轮显示预览选项）
→ 点击“转一下” → 3 列滚动，依次停止 → 结果卡片
→ 锁定“主料” → 点击“再转一次” → 其余 2 列滚动、停止 → 新结果
→ 点击“就它了” → 庆祝反馈 → [分享结果] / [重新开始]
```

### 5.2 游戏类（聚会 / 情侣互动）

```
首页 → “聚会挑战” → 老虎机页（若为“情侣互动”，顶部额外显示尺度筛选，默认“温和”）
→ “转一下” → 结果卡片（“谁来 × 做什么 × 附加条件”）
→ 执行后点击“完成”（轮数 +1，有庆祝反馈）→ 主按钮变为“下一轮” → 继续
→ 不想做 → 点击“换一个”（不计次数、不受限制）→ 重新转动
```

情侣互动、便利店调酒首次进入时显示一次性须知（见 F17），不阻断操作。

### 5.3 排除不喜欢的选项

```
老虎机页 → 点击某一列 → 该列的选项列表展开
→ 点击“羊肉”→ 显示灰色 + 删除线（已排除）→ 收起
→ 之后转动不再出现“羊肉”
→ 想恢复时再次展开，点击“羊肉”即可恢复
```

### 5.4 创建自定义老虎机

```
首页 → “新建老虎机” → 编辑器（名称、列、候选项、句式（选填））→ 保存 → 进入该老虎机页
或：预设老虎机页 → 设置 → “复制为我的老虎机” → 编辑器（已带入内容）→ 保存
```

### 5.5 分享与导入模板

```
自定义老虎机页 → 设置 → “分享模板” → 生成链接 → 系统分享 / 复制
朋友打开链接 → 导入预览页（显示模板名称、列数、选项数，内容默认折叠）
→ [直接转一下]（临时使用，不保存）或 [保存到我的老虎机]
```

## 7. 功能需求

### F01 首页与场景入口【P0】

**描述：** 展示 5 个预设场景卡片和“我的老虎机”区域。

**规则：**
1. 预设卡片按 §4 的顺序排列，每张卡片包含名称、一句话描述、视觉元素（由 UX 定义）。
2. 点击卡片直接进入对应的老虎机页，中间**不插入任何配置步骤**。【已确认】
3. “我的老虎机”区域按最近使用时间倒序列出自定义模板，显示名称和列名摘要（例如“早餐 × 饮品”）。
4. 没有自定义模板时显示空状态：一句说明 +“新建老虎机”按钮。
5. 有自定义模板时，列表末尾始终有“新建老虎机”入口。
6. 页脚有“反馈”入口（见 F17）。

**验收标准：**
- [ ] 从打开首页到进入老虎机页只需 1 次点击。
- [ ] 新用户首页能看到 5 个预设卡片和“我的老虎机”的空状态。
- [ ] 保存一个自定义模板后返回首页，能在列表第一位看到它。
- [ ] 刷新页面后，自定义模板列表保持不变。

### F02 老虎机页与转动【P0】

**描述：** 老虎机页的核心交互。

**页面元素（布局见 UX）：** 返回、模板名称、设置按钮、尺度筛选（仅有尺度的模板显示）、N 列滚轮、每列的锁定按钮、主按钮、结果卡片区域、剩余次数（仅在设置了次数上限时显示）。

**状态机：**

| 状态 | 说明 | 进入条件 |
|---|---|---|
| `idle` | 初始状态，还没转过 | 进入页面；点击“重新开始” |
| `spinning` | 有列正在滚动或依次停止 | 点击主按钮（转一下 / 再转一次 / 换一个 / 下一轮） |
| `result` | 已出结果，等待用户操作 | 最后一列停止 |
| `accepted` | 决策类：已点击“就它了”；游戏类：已点击“完成” | 在 `result` 状态点击“就它了”或“完成” |

**规则：**
1. `idle` 状态下，滚轮显示每列随机选取的可用候选项作为预览，**不算作结果**：不能锁定，不显示结果卡片。
2. 点击主按钮后，所有**未锁定**的列开始滚动，锁定的列保持不动。
3. `spinning` 状态下，主按钮、锁定按钮、列展开、尺度筛选、可选列开关、设置按钮**全部不可用**（P1 的急停是例外，见 F19）。
4. 最后一列停止后进入 `result` 状态，显示结果卡片。
5. **结果在转动开始时就已确定**，动画只负责展示，不能根据动画过程改变结果。
6. 离开老虎机页（返回、刷新、关闭）后，本次的结果、锁定、已用次数、轮数**不保存**，下次进入回到 `idle`。
7. 主按钮的文案（具体措辞由 UX 确定）：

| 状态 | decision | game |
|---|---|---|
| idle | 转一下 | 转一下 |
| result | 再转一次 | 换一个 |
| accepted | 重新开始 | 下一轮 |

**验收标准：**
- [ ] 进入页面时看到 N 列预览，不能锁定。
- [ ] 点击“转一下”后所有列滚动，并在 2.5 秒内全部停止并显示结果。
- [ ] 转动过程中连续点击主按钮，不会触发第二次转动。
- [ ] 转动过程中点击锁定按钮或列，没有任何效果。
- [ ] 刷新页面后回到 `idle`，没有锁定。

### F03 转动动画与反馈【P0】

**描述：** 产品的体验核心。本节只定义必须满足的要求，具体曲线、时长和视觉在 UX_DESIGN 中确定。

**规则：**
1. 列从左到右**依次停止**。
2. 总时长（从点击到最后一列停止）**不超过 2.5 秒**；第一列停止大约在 1.0–1.4 秒，列间隔大约 0.25–0.4 秒（UX 阶段调参确认）。
3. 只有部分列在转时，按照这些列的从左到右顺序依次停止，节奏不变。
4. 停止时要有减速和轻微回弹（或等效的“落定感”）。
5. 每一列停止时有视觉反馈（例如高亮、轻微缩放）。
6. 结果卡片在最后一列停止后出现，有入场动画。
7. “就它了”和“完成”触发庆祝反馈（例如撒花，强度由 UX 定义）。
8. 系统开启“减少动态效果”（`prefers-reduced-motion`）时：转动时长缩短到 0.8 秒以内，去掉回弹和庆祝动画，只保留淡入淡出。
9. 动画目标为 60fps，在中端手机上不能明显掉帧。

**验收标准：**
- [ ] 3 列转动时，肉眼可以看出从左到右依次停止。
- [ ] 锁定中间一列后转动，左右两列依次停止，中间一列完全不动。
- [ ] 开启系统“减少动态效果”后，转动时长不超过 0.8 秒，没有撒花。
- [ ] 在 iPhone 11 或同级 Android 设备上转动 10 次，没有明显卡顿。

### F04 锁定列【P0】

**规则：**
1. 只能在 `result` 或 `accepted` 状态锁定或解锁，`idle` 和 `spinning` 状态不可用。
2. 每列有独立的锁定按钮，点击切换锁定/解锁，锁定状态有明确的视觉区分。
3. 锁定的列在下一次转动中保持当前值。
4. **全部列都被锁定时**，主按钮不可用，并提示“全都锁住了，解锁一列再转”。
5. 游戏类场景中，锁定在多轮之间保持，直到用户解锁或离开页面。
6. 锁定的列的当前值被排除时，该列**自动解锁**（见 F08）。
7. 锁定的列的当前值因尺度变化不再可用时，该列**自动解锁**（见 F09）。
8. 点击“重新开始”（决策类）会清除所有锁定。

**验收标准：**
- [ ] 第一次转动之前，锁定按钮不可点击。
- [ ] 锁定第 1 列后再转，第 1 列的值不变，其余列重新取值。
- [ ] 3 列全部锁定后，主按钮不可点击，并显示提示文案。
- [ ] 游戏类场景中锁定一列，点击“完成”→“下一轮”，该列仍然锁定。

### F05 决策类流程与结果卡片【P0】

**结果卡片内容【已确认 D4】：**
1. **结果标签**：各列结果的 `label`，用“×”连接。
2. **结果句式**：用结果填充模板的 `sentence`。模板没有句式时不显示这一行，只显示结果标签。
3. **结果提示**：模板定义了 `note` 时显示一行固定提示（例如 `mix` 的调配比例）。没有就不显示。
4. 场景专属提示：`cook` 显示“AI 推荐菜谱即将上线”（见 F17）。
5. 操作按钮。

不设候选项说明（`detail`）【已确认】，卡片保持简洁。游戏类场景使用同样的卡片内容。

**决策类按钮规则：**

| 状态 | 可用操作 |
|---|---|
| result | **就它了**、再转一次（主按钮）、锁定、列展开 |
| accepted | **分享结果**、重新开始（主按钮）、锁定、列展开 |

- “就它了”：进入 `accepted`，触发庆祝反馈，结果卡片切换为“已决定”样式，记录 `accept` 事件。
- `accepted` 状态下锁定或解锁一列，回到 `result` 状态（相当于用户反悔，开始重新收敛）。
- “重新开始”：清除结果、锁定、已用次数，回到 `idle`。

**防疲劳轻提示【已确认 D17】：** 决策类场景中，同一次页面停留内**连续转动 8 次**仍未点击“就它了”时，显示一次 toast：“转了好多次啦，试试锁定喜欢的列？”。每次页面停留最多显示 1 次，不拦截任何操作。

**验收标准：**
- [ ] `cook` 转出结果后，卡片显示 3 个标签、一句填充好的句式、AI 轻提示。
- [ ] 没有句式的自定义模板，卡片只显示“A × B × C”。
- [ ] 点击“就它了”后出现庆祝反馈，主按钮变为“重新开始”。
- [ ] 连续转动 8 次后出现 1 次轻提示，第 9、10 次不再出现。

### F06 游戏类流程【P0】

**按钮规则：**

| 状态 | 可用操作 |
|---|---|
| result | **完成**、换一个（主按钮）、锁定、列展开 |
| accepted | 下一轮（主按钮）、锁定、列展开 |

**规则：**
1. “换一个”：重新转动未锁定的列，**不计次数、永不受限**。【已确认】
2. “完成”：轮数 +1，触发庆祝反馈，进入 `accepted`。

6. 游戏类场景**没有**防疲劳提示。

**验收标准：**

- [ ] 点击“完成”后轮数从“第 1 轮”变为“第 2 轮”。
- [ ] 设置面板中看不到重转次数选项。

### F07 重转次数【P0，已确认 D17】

**仅适用于决策类场景**（`cook`、`date`、所有自定义模板）。

**规则：**
1. 设置面板中提供“重转次数”选项：不限、1、2、3、5、10。默认“不限”。
2. 语义：**第一次转动不计入**，之后每次转动（包括部分列锁定后的转动）消耗 1 次。
3. 设置了上限时，主按钮附近显示“还剩 N 次”。
4. 剩余 0 次时：主按钮不可用，文案改为“命运已定”，“就它了”按钮突出显示。
5. 次数在 `result` 状态中途修改时立即生效：剩余次数 = max(0, 新上限 − 已用次数)。
6. 设置值按模板保存在本地（下次进入保留）；**已用次数不保存**，离开页面后重置。
7. “重新开始”会清零已用次数。

**验收标准：**
- [ ] 设置为 3 次：首次转动后显示“还剩 3 次”，再转 3 次后主按钮显示“命运已定”且不可点击。
- [ ] 已用 2 次时把上限改为 1，剩余立即变为 0。
- [ ] 离开页面再进入，上限设置保留，剩余次数恢复为完整值。

### F08 列展开、排除与恢复【P0，已确认 D8】

**描述：** 点击某一列，展开这一列的全部选项，在这里排除或恢复。

**规则：**
1. 在 `idle`、`result`、`accepted` 状态下点击某一列滚轮区域，打开该列的展开面板；`spinning` 时不可用。
2. 面板显示该列全部候选项的 `label`；属于内容分组的候选项附带分组小标记（例如“接触”）。
3. 候选项的显示状态：

| 状态 | 显示 |
|---|---|
| 可用 | 正常 |
| 已排除 | **灰色 + 删除线**【已确认】 |
| 当前尺度不可用 | 正常文字、降低透明度 + 尺度徽标（如“升温”），**不使用删除线**，以便和“已排除”区分 |
| 当前结果值 | 额外高亮标记“当前” |

4. 点击可用项 → 排除；点击已排除项 → 恢复。尺度不可用的项也可以排除或恢复（排除状态独立于尺度）。
5. 面板顶部显示“已排除 N 项”，并提供“全部恢复”。
6. **每列至少保留 1 个未排除的候选项**：试图排除最后一个时，操作无效并提示“这一列至少要留 1 个”。
7. 排除**永久保存在本机**，离开页面、刷新后依然生效。【已确认】
8. 预设模板的排除作为“本地偏好”单独保存，不修改预设本身。自定义模板的排除直接保存在模板数据里。
9. 如果被排除的项正是该列的**当前结果值**：
   - 该列自动解锁；
   - 滚轮上的当前值显示为灰色 + 删除线；
   - 结果卡片保持显示，但该项标记为已排除；
   - 状态从 `accepted` 回到 `result`；
   - 下一次转动时该列必定换值。
10. 设置面板的“恢复全部排除”一次性恢复该模板所有列的排除（需要二次确认）。

**验收标准：**
- [ ] 在 `cook` 中排除“羊肉”，转动 50 次，“羊肉”一次都不出现。
- [ ] 刷新页面后再次展开该列，“羊肉”仍为灰色 + 删除线。
- [ ] 点击“羊肉”可以恢复，恢复后可以被转到。
- [ ] 某列只剩 1 个未排除项时，无法再排除。
- [ ] 当前结果是“羊肉”且该列已锁定时排除“羊肉”，该列自动解锁，下一次转动该列换值。
- [ ] `party` 的饮酒类候选项首次进入时即显示为已排除。
- [ ] 在 F22 整组排除某分组后，展开列中该组候选项全部显示为灰色 + 删除线；单独点击其中一项可以恢复该项。

### F09 尺度筛选【P0】

**适用：** 模板中存在带 `intensity` 的候选项时显示（V0.1 预设中仅 `couple`；复制自 `couple` 的自定义模板也会保留）。

**规则：**
1. 老虎机页顶部显示 3 档分段选择器，名称由模板定义（例如 温和 / 心动 / 升温）。
2. 选择第 L 档时，`intensity ≤ L` 的候选项可用；没有 `intensity` 的候选项视为 1 级。
3. 默认档位见 §4；用户的选择按模板保存在本地。
4. `spinning` 时不可切换；切换在下一次转动时生效，当前已显示的结果不变。
5. 切换后，如果锁定列的当前值超出新档位，该列自动解锁（见 F04）。
6. 尺度不会改变排除状态，两者独立。
7. 某列在当前尺度 + 排除条件下没有可用候选项时，见 §9 异常 E05。

**验收标准：**
- [ ] `couple` 默认为“温和”，连续转动 30 次，不出现 `intensity > 1` 的候选项。
- [ ] 切换到“升温”后，3 个尺度的候选项都可能出现。
- [ ] 刷新页面后尺度档位保持不变。
- [ ] 锁定一个 2 级的值后切回“温和”，该列自动解锁。

### F10 可选列【P0】

**适用：** 模板定义了可选列时（V0.1 为 `couple` 的“附加规则”、`mix` 的“再加一种”，均默认关闭）。

**规则：**
1. 提供开关，例如“加点规则”“再加一种”；默认状态由模板定义（`couple`、`mix` 均默认关闭【已确认】）。开关的位置由 UX 确定（`mix` 的开关建议直接放在老虎机页上，而不是藏在设置里）。
2. 关闭时，该列不显示、不参与转动、不出现在结果卡片中。
3. 开启时，该列作为最后一列显示。
4. 在已有结果时开启：新列显示为“?”占位（不算锁定），下一次转动时取值；结果卡片暂时不显示这一列。
5. 在已有结果时关闭：该列以及它的锁定状态被移除，结果卡片相应更新。
6. 开关状态按模板保存在本地。
7. 可选列计入列数上限（4 列）。
8. 结果句式：可选列开启时，在句式末尾追加该列定义的 `sentenceSuffix`（例如“，规则：{附加规则}”）。

**验收标准：**
- [ ] `couple` 默认显示 3 列；打开“加点规则”后显示 4 列。
- [ ] `mix` 默认显示 2 列，句式为“用{基酒}兑{饮料}”；打开“再加一种”后显示 3 列，句式末尾追加“，再加点{再加一种}”。
- [ ] 打开后转动，结果卡片的句式包含附加规则。
- [ ] 刷新页面后开关状态保持。

### F11 随机规则【P0】

**规则：**
1. 每个未锁定的列从**可用候选项**中独立抽取 1 项。
2. 按权重随机：抽中概率 = 该项 `weight` / 可用项的 `weight` 总和。`weight` 默认为 1，即默认等概率。V0.1 编辑器不开放权重，只有预设可以使用。
3. **不连续重复**：某列有 ≥ 2 个可用候选项时，本次结果不得与该列上一次的结果相同（只对参与转动的列生效；`idle` 的预览不算“上一次”）。
4. 随机源使用 `crypto.getRandomValues`（不可用时降级为 `Math.random`）。
5. 互斥规则（F21，P1）：只有内容抽查证明必要时才实现；实现时只能用于预设，且不能导致任何一列没有可选项（发生冲突时，该列忽略互斥规则）。
6. `idle` 的预览值同样从可用候选项中随机选取。

**验收标准（单元测试）：**
- [ ] 一列有 3 个等权可用项，抽 3000 次，每项出现次数在 900–1100 之间（不连续重复规则会让分布更均匀，这个范围仍然成立）。
- [ ] 一列有 ≥ 2 个可用项时，连续 1000 次转动中不出现相邻两次相同。
- [ ] 一列只有 1 个可用项时，每次都返回该项，不报错。
- [ ] 锁定列的值在转动前后保持一致。
- [ ] 已排除或超出尺度的候选项永远不会被抽中。

### F12 自定义老虎机【P0】

**12.1 创建**
- 方式 A：首页“新建老虎机” → 空白模板：名称“我的老虎机”，3 列，列名“第 1 列 / 第 2 列 / 第 3 列”，候选项为空。
- 方式 B：预设或自定义模板的设置面板 → “复制为我的老虎机” → 编辑器载入副本：名称加“（副本）”，候选项连同排除状态、`intensity`、`tags` 一并复制，玩法类型、可选列、尺度名称、内容分组、`note`、`notice` 保持不变。
- 新建模板的玩法类型为 `decision`。V0.1 编辑器不提供修改玩法类型。

**12.2 编辑器字段与限制**

| 字段 | 必填 | 限制 |
|---|---|---|
| 模板名称 | 是 | 1–20 字 |
| 列 | 是 | 1–4 列（包括可选列） |
| 列名 | 是 | 1–8 字 |
| 候选项 label | 是 | 每列 2–30 项；每项 1–8 字（建议 6 字以内，超过 6 字时提示可能显示不全） |
| 结果句式 | 否 | ≤ 60 字；通过“插入列”按钮插入占位，不需要手动输入占位语法 |

- 同一列内候选项 label 去掉首尾空格后不能重复，重复时提示并拒绝添加。
- 所有文本作为纯文本处理，不解析 HTML 或 Markdown。

**12.3 编辑器操作**
- 列：添加（不超过 4 列）、删除（至少保留 1 列；列中有候选项时需要二次确认）、重命名。
- 候选项：逐个添加；**批量添加**——粘贴或输入多项，按换行、中英文逗号、顿号、空格拆分，自动去掉空项和重复项，超过 30 项时只保留前 30 项并提示。
- 候选项：编辑 label、删除、排除/恢复（显示方式与 F08 一致）。
- 删除某一列时，句式中对应的占位自动移除。
- 复制来的可选列在编辑器中标注“可选列”，可以编辑候选项和列名，但不能修改“可选”属性。V0.1 不能新建可选列。
- 复制来的候选项保留 `intensity`/`tags`，但编辑器中不显示也不能编辑；新添加的候选项没有这两项。复制来的 `note`、`notice`、内容分组同样保留且不可编辑。

**12.4 保存与退出**
- 点击保存时校验 12.2 的全部规则；不通过时就地标出错误项，不能保存。
- 保存成功后进入该模板的老虎机页。
- 有未保存修改时点击返回，弹出确认“放弃修改？”。
- 自定义模板最多 50 个，达到上限后“新建”和“复制”不可用并提示。

**12.5 删除**
- 在设置面板中“删除这个老虎机”，需要二次确认，删除后回到首页。

**验收标准：**
- [ ] 新建空白模板后直接保存，提示“每列至少 2 个选项”，不能保存。
- [ ] 在一个输入框粘贴“豆浆、油条、包子\n煎饼”，生成 4 个候选项。
- [ ] 复制 `cook` 后修改一项并保存，`cook` 预设本身不变。
- [ ] 编辑中途返回，弹出放弃确认；确认后修改丢失。
- [ ] 删除第 2 列后，句式中的第 2 列占位消失。
- [ ] 删除模板后它从首页消失，刷新后也不再出现。

### F13 本地持久化【P0】

**存储内容（数据结构见 TECH_DESIGN）：**

| 数据 | 说明 |
|---|---|
| 自定义模板 | 完整内容，包括排除状态 |
| 预设偏好 | 每个预设的排除列表、尺度档位、可选列开关、重转次数设置 |
| 自定义模板偏好 | 尺度档位、可选列开关、重转次数设置 |
| 应用状态 | 已看过的一次性提示、最近使用时间、回访标记日期 |

**规则：**
1. 所有数据带 `schemaVersion`，读取时版本较旧则迁移，版本较新或数据损坏则忽略该条，不导致应用崩溃。
2. 预设候选项使用稳定的 `id`；预设内容更新后，偏好中引用的已不存在的 `id` 会被忽略，新增的候选项默认可用（除非它带有默认排除的标签，例如 `alcohol`）。
3. **不保存**：本次的结果、锁定、已用次数、轮数。
4. localStorage 不可用（例如部分浏览器的隐私模式）时，应用仍可正常使用；首次需要写入时提示一次“当前浏览器无法保存，关闭页面后设置会丢失”。
5. 写入失败（存储空间满）时提示“保存失败，存储空间不足”，不能静默丢失数据。

**验收标准：**
- [ ] 修改排除、尺度、可选列、重转次数后刷新页面，全部保留。
- [ ] 手动把 localStorage 中的数据改成非法 JSON 后刷新页面，应用正常打开（相关数据回到默认值）。
- [ ] 在隐私模式下能完成一次完整的转动流程。

### F15 模板链接分享与导入【P0，已确认 D12】

**15.1 分享**
1. 入口：自定义模板设置面板中的“分享模板”。预设模板不需要模板分享，直接分享页面链接即可。
2. **链接总长度 ≤ 200 字符**（含域名）【已确认】。纯前端把模板编码进 URL 无法满足这一点（典型模板压缩后仍有 300–600 字符，微信复制时中文还会膨胀数倍），因此采用**自建极简短链接**【已确认：方案 B，接受简单后端】：
   - 点击“分享模板”→ 前端把模板数据提交到短链接接口 → 接口校验后存储，返回短 ID → 链接为 `{域名}/s/{ID}`（ID 为 8 位字母数字，链接约 30 字符）。
   - 打开 `/s/{ID}` → 前端按 ID 取回模板数据 → 进入导入预览页。
   - 每次分享都生成新 ID，不做去重；V0.1 的数据不设过期时间。
   - 服务端只存模板数据本身，**不存储 IP、设备标识等任何个人信息**；没有公开列表，也不能按 ID 以外的方式查询。
   - 服务端对写入做基础限流（暂定同一来源每分钟最多 10 次），并按 F12 的规则重新校验数据，不合法则拒绝。
   - 提供一个**仅限开发者使用的管理脚本**，可以按 ID 删除模板，用于处理违规内容。
   - 兜底【建议】：短链接接口失败或超时（3 秒）时，自动改用长链接 `{域名}/import#t={编码数据}`，并提示“短链接生成失败，已改用长链接”。长链接不受 200 字符限制。
3. 编码/存储内容：模板名称、玩法类型、列（列名、是否可选、可选列的默认开关状态、`sentenceSuffix`）、候选项（`label`、`intensity`、`tags`）、句式、尺度名称、内容分组、`note`、`notice`、数据版本号。
4. **只编码未排除的候选项**；发送者的偏好（尺度档位、重转次数）不编码。
5. 模板数据大小超过上限（暂定 8KB，TECH_DESIGN 中确定）时，提示“模板太大，分享不了。试着删掉一些选项”。
6. 调用系统分享或复制，规则与 F14 相同。

**15.2 导入**
1. 打开链接 → 导入预览页，显示：模板名称、列数、每列名称和选项数。**选项内容默认折叠**，点击“查看全部选项”后展开。
2. 操作：
   - **直接转一下**：以临时模式进入老虎机页（不保存）。页面顶部显示横幅“这是朋友分享的老虎机 [保存]”。临时模式下的排除、尺度等修改只在本次有效。
   - **保存到我的老虎机**：保存为新的自定义模板（同名时允许保存，名称后加“（2）”等后缀），然后进入老虎机页。
3. 导入的数据按 F12 的全部限制重新校验，不合法则视为链接损坏（E07）。
4. 同一份模板重复导入，生成多个副本，不做去重。
5. 自定义模板已满 50 个时，“保存”不可用并提示，“直接转一下”仍然可用。

**验收标准：**
- [ ] 一个 3 列 × 10 项的模板分享后，在另一台设备的浏览器打开，内容完全一致。
- [ ] 从导入预览页点击“直接转一下”可以开始转（打开链接后 1 次点击）。
- [ ] 临时模式下离开页面，首页的“我的老虎机”中没有这个模板。
- [ ] 生成的短链接（含域名）不超过 200 字符。
- [ ] 打开不存在的短链 ID 或被截断的长链接，显示“链接已损坏”错误页，并提供“回到首页”。
- [ ] 模拟短链接接口不可用，点击分享后在 3 秒内改用长链接，长链接可以正常导入。
- [ ] 直接调用接口提交不合法的数据（超过 8KB、列数超限、含非法字段），被拒绝。
- [ ] 用管理脚本删除某个 ID 后，打开该链接显示“链接已损坏”。
- [ ] 超长模板点击分享时出现大小提示，不生成链接。
- [ ] 被排除的候选项不会出现在对方导入的模板中。

### F18 音效与振动【P2，V0.2 实现；已确认】

V0.1 不做。以下是已确认的方向，供 V0.2 使用：

- 风格**尽量简单**：滚动时轻微的“哒哒”声，每列停止时一声短促的落定音，确定结果（“就它了”/“完成”）时也只是**一个简单的短音**，不做复杂的庆祝音乐。
- 默认开启，老虎机页常驻静音按钮，状态全局保存在本地。
- 音频全部用 Web Audio API 在代码中合成，**不使用任何第三方素材或音频文件**（避免版权问题）。如果合成效果不够好，再考虑用条款明确允许商用的 AI 工具生成。
- 浏览器要求用户交互后才能播放声音：第一次点击“转一下”时初始化音频；失败时静默，不影响转动。
- 支持 `navigator.vibrate` 的设备上，每列停止时轻振一次。

V0.1 的约束：动画实现要在“每列开始滚动 / 每列停止 / 确定结果”这几个时刻留出事件回调，方便 V0.2 接入音效。

### F22 内容分组整组排除【P0，已确认】

**描述：** 模板可以定义若干“内容分组”，每组对应一个 `tag`。用户可以一键排除或恢复整组候选项，例如聚会时不想要任何身体接触类挑战。

**V0.1 预设中的分组：**

| 模板 | 分组名称 | tag | 默认 |
|---|---|---|---|
| `party` | 身体接触 | `touch` | 开启 |
| `party` | 隐私话题 | `privacy` | 开启 |
| `party` | 场外互动（联系场外 / 发布内容） | `outside` | 开启【已确认】 |
| `party` | 饮酒 | `alcohol` | **整组排除**【已确认】 |

**规则：**
1. 设置面板中显示“内容类型”区域，列出该模板的全部分组，每组一个开关和数量（例如“身体接触 · 6 项”）。没有分组的模板不显示这个区域。
2. **整组排除是批量操作**，结果写入 F08 的排除状态，不另存一套筛选状态：
   - 关闭开关 → 该组的全部候选项设为已排除；
   - 打开开关 → 该组的全部候选项恢复。
3. 开关显示：组内全部已排除时为“关”；否则为“开”，部分排除时附带“已排除 x/y”。
4. 一个候选项属于多个分组时，任一分组关闭都会排除它；打开某个分组时，只恢复**不属于其他已关闭分组**的候选项。
5. 整组排除会导致某列没有未排除的候选项时，整个操作不执行，提示“这样『{列名}』就没有选项了”。预设内容需要保证：即使所有分组都关闭，每列仍至少有 3 个可用项。
6. 当前结果值被整组排除时，按 F08-9 处理（自动解锁等）。
7. 模板定义的默认整组排除（如 `alcohol`），在用户第一次进入该模板时生效；之后以用户的操作为准。
8. `spinning` 时不可操作。

**验收标准：**
- [ ] 首次进入 `party`，设置面板中“饮酒”为关闭，其余分组为开启。
- [ ] 关闭“身体接触”后转动 50 次，不出现任何 `touch` 候选项。
- [ ] 关闭“身体接触”后在展开列中单独恢复一项，开关仍显示“开”并附带“已排除 5/6”。
- [ ] （用测试数据验证）同时属于两个分组的候选项：关闭两组后只打开其中一组，该项仍保持排除。
- [ ] 刷新页面后各分组状态保持不变。

## 9. 异常与边界情况

| ID | 情况 | 处理 |
|---|---|---|
| E01 | 全部列锁定 | 主按钮不可用 + 提示“全都锁住了，解锁一列再转” |
| E02 | 转动中重复点击 | 忽略 |
| E03 | 转动中页面切到后台 | 结果已确定；回到页面时直接显示最终结果，进入 `result` |
| E04 | 转动中屏幕旋转或尺寸变化 | 动画继续或直接跳到最终结果，不能出现错位 |
| E05 | 某列没有可用候选项（排除 + 尺度共同导致） | 主按钮不可用，提示“『{列名}』在当前尺度下没有可用选项”，并提供“调高尺度”或“去恢复”的入口。预设内容需要保证每一档尺度下、以及所有内容分组都关闭时，每列至少 3 个可用项，让这种情况只会出现在自定义模板中 |
| E06 | 访问不存在的自定义模板（已删除或在别的设备上） | 错误页“这个老虎机不见了” + 回到首页 |
| E07 | 分享链接损坏、解码失败、校验失败 | 错误页“链接已损坏，请让朋友重新分享” + 回到首页 |
| E08 | 分享链接的数据版本高于当前应用 | 提示“这个模板来自新版本，请刷新页面后重试”；仍然失败时按 E07 处理 |
| E09 | localStorage 不可用 | 见 F13-4 |
| E10 | 存储空间不足 | 见 F13-5 |
| E11 | 自定义模板达到 50 个 | 新建、复制、导入保存不可用，并提示 |
| E12 | 候选项 label 超过显示宽度 | 滚轮中截断并加省略号；结果卡片中完整显示 |
| E13 | 只有 1 列的模板 | 正常工作；所有列都锁定时按 E01 处理 |
| E14 | 网络断开 | 已加载的页面完全可用；统计静默失败；“分享模板”提示“网络不可用”，打开短链接时显示“网络不可用，请稍后重试” + [重试] |
| E16 | 短链接接口失败或超时（分享时） | 3 秒后自动改用长链接，见 F15 |
| E17 | 短链接接口失败（打开 `/s/{ID}` 时，非 404） | 显示“加载失败” + [重试]，不按“链接已损坏”处理 |
| E18 | 写入被限流 | 提示“分享太频繁了，稍后再试” |
| E15 | 同一个模板在两个标签页中被编辑 | 以后保存的为准，不做冲突处理 |
